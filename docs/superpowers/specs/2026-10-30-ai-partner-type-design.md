# AIパートナータイプ診断 設計書

作成日: 2026-10-30
リポジトリ: `ai-partner-type`（GitHub `KendrickMalar/ai-partner-type`、公開）

## 1. 目的と背景

ラブタイプ診断（4軸×2択＝16タイプ）の作りを借りて、「あなたに合うAIパートナー」を診断するWebサイトを作る。

- **誰に**: ChatGPT や Claude などのAIを毎日使っている人
- **成功の形**: 結果をSNS（主に X）でシェアしてもらうこと
- **結果の主役**: 本人の性格ではなく、「あなたに合うAIパートナー像」。たとえば「あなたには、遠慮なく指摘してくる先回り型のAIが合う」

## 2. ゴール・やらないこと・失敗とみなすこと

### ゴール
- 約2分で終わる20問の診断で、16タイプのうち1つを出す
- 結果ページは、そのままシェアしたくなる見た目にする（ロボットのキャラクター、タイプ名、短い説明）
- 結果URLを X に貼ると、そのタイプ専用の画像がカードで表示される
- 無料で公開する（GitHub Pages）

### やらないこと
- ChatGPT / Claude に貼る設定文（プロンプト）は**付けない**（ユーザー決定）
- 診断中に AI API を呼ばない。結果はすべて、あらかじめ用意した固定の16タイプから選ぶ（ユーザー決定）
- ログイン、データベース、回答の保存・送信
- アクセス解析（入れない。ユーザー決定。あとから追加できる作りにはしておく）
- 独自ドメイン（使わない。私の判断）
- 多言語対応（日本語のみ。私の判断）

### 失敗とみなすこと
- ラブタイプ診断の名前・絵・文章・タイプ名を写したり、それと分かるほど似せたりすること。借りるのは「4軸×2択＝16タイプ」という作りだけ
- 本人の性格を強く決めつける言い方（例:「あなたは怠け者」）。結果は「合うAI」の説明として、前向きに書く
- シェアしたときに画像が出ない・崩れる

## 4. 画面と流れ

1. **トップ**（`/`）: タイトル、ひとこと説明、「診断をはじめる」ボタン、16タイプ一覧へのリンク
2. **質問**（`/quiz/`）: 1画面に1問。答えは5段階（あてはまる／ややあてはまる／どちらでもない／ややあてはまらない／あてはまらない）。進み具合のバー、ひとつ前に戻るボタン。最後の問いに答えると結果ページへ移動する
3. **結果**（`/types/<コード>/`、16ページ）:
   - ロボットの絵とキャラ名を大きく出す
   - 4つの軸のバー（どちらにどれだけ寄ったか）。点数は URL のクエリで渡し、クエリがなければ（共有リンクから来た人）バーは「タイプの側」を示すだけにする
   - どんなパートナーか（2〜3段落）
   - そのAIと相性のよい使い方の例（3つ程度）
   - 「Xでシェア」ボタン、「もう一度診断する」、16タイプ一覧へのリンク
4. **16タイプ一覧**（`/types/`）: 16体の絵と名前を並べ、各結果ページへリンク

結果ページは診断した本人も、シェアされたリンクから来た人も見る。共有から来た人が「自分もやりたい」と思えるよう、ページ上部に「診断をはじめる」ボタンも置く。

## 5. 採点

- 各軸5問。各問いはその軸のどちらかの側に寄せて書き、5段階の回答を +2〜-2 に換算する（逆向きの問いは符号を反転）
- 軸ごとの合計（-10〜+10）の符号で側を決める
- **合計がちょうど0のとき**の寄せ方は作る人が決めてよい（例: その軸の最後の問いの答えで決める）。必ずどちらかに決まるようにする
- 回答は保存も送信もしない。計算はブラウザの中だけで行う

## 6. シェア

- 「Xでシェア」は X の投稿画面（intent URL）を開く。本文は「私に合うAIパートナーは『<キャラ名>』でした」＋結果ページの URL＋ハッシュタグ1つ（ハッシュタグの文言は作る人が決めてよい）
- 結果ページごとに `og:title`・`og:description`・`og:image`、`twitter:card=summary_large_image` を入れる。`og:image` は絶対 URL（`https://kendrickmalar.github.io/ai-partner-type/...`）
- シェア画像（1200×630 の PNG）を16枚、ビルド時に作る。中身はロボットの絵、キャラ名、軸のラベル、サイト名
- X のカードは PNG / JPG が必要なため、SVG から PNG への変換をビルドに含める

## 7. 作り方

- 静的サイトとして作り、GitHub Actions で GitHub Pages に公開する。サーバーは使わない
- フレームワークは作る人が決めてよい。条件は、16の結果ページが別々の HTML として出力され、それぞれにメタタグが入ること（クライアント側だけで切り替える作りでは X のカードが出ないため不可）。**私の判断**: Astro の静的出力がこの条件に合い、手軽
- GitHub Pages はリポジトリ名のサブパス（`/ai-partner-type/`）で公開されるため、リンクと画像のパスをそれに合わせる
- タイプの文章・質問文はコードと分けたデータファイル（JSON や TS）に置き、あとで直しやすくする

## 8. キャラクター（ロボット）

- 16体を SVG で描く。円・四角などの図形を組み合わせたシンプルな絵でよい
- 軸ごとに見た目の要素を対応させると、描き分けと統一感の両方が出せる（私の案。例: 主導＝アンテナの有無、温度＝暖色／寒色、発想＝四角い頭／丸い頭、話し方＝口の形）。最終的な描き方は作る人が決めてよい
- キャラ名は「性格が一言で伝わる日本語＋ボット」程度の長さ（例:「おせっかい参謀ボット」）。16体の名前・説明文は作る人が決めてよい（公開前の確認は不要）
- 名前はシェア画像に焼き込まれ、X のカードはキャッシュされるため、公開前に作る人が一度読み直して整える

## 9. 文章のトーン

- 前向きで、AIを毎日使う人が「あるある」と思える具体例を入れる
- 質問は「AIにこうしてほしい／こうされるとうれしい」という好みを聞く形で書く。各軸5問のうち1〜2問は逆向き（もう片方の側に寄せた文）にする
- 結果の説明文は「このAIはあなたに〜する」という書き方にし、本人の性格の描写は控えめにする
- 性格を決めつけない。主語は「あなたに合うAI」
- 1文を短く

## 10. 作る人に任せること

- フレームワーク、CSS の書き方、アニメーション
- 質問文20問、16タイプの名前と説明文（公開前の確認は不要）
- 色、フォント（無料で使えるもの）、サイト名
- 同点時の寄せ方、ハッシュタグの文言

## 11. 完成の確かめ方

- 20問に答えると、必ず16タイプのどれかの結果ページに移る
- 4つの軸それぞれについて、全部「あてはまる」と全部「あてはまらない」で、別の側になる
- 16の結果ページそれぞれの HTML に、正しい `og:image` の絶対 URL が入っている。その PNG が存在する
- GitHub Pages に公開した URL を X のカード確認（または投稿のプレビュー）で開き、画像が出る
- スマホ幅（375px）で崩れない

## 12. 公開の手順

- GitHub に公開リポジトリ `KendrickMalar/ai-partner-type` を作る操作と、最初の push は、実行前にユーザーに確認する（まだ作っていない）
- Pages の公開元を「GitHub Actions」に設定する
